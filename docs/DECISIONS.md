# Decisions log

Each entry: id, decision, why, alternatives considered.

| ID | Decision | Why |
|---|---|---|
| D-001 | Add the `scripting` permission and ship `pageWorld.js` at the extension root. | Required by `@inboxsdk/core` MV3 (`background.js` injects `pageWorld.js` into the MAIN world). The spec lists only storage/alarms/notifications. |
| D-002 | Rewrite the outgoing body with `composeView.registerRequestModifier` (async) rather than mutating the DOM in `presending`. | `presending` is synchronous in InboxSDK 2.2.29, so it can't await the 3 s server call. The request modifier is awaited, and InboxSDK falls back to the original body if the promise rejects (fail-soft). Cancel-then-resend inside `presending` is kept as a documented fallback only. |
| D-003 | Build with `@crxjs/vite-plugin` 2.7.1 + Vite 6. | 3.0.0 is too fresh. Fallback to plain Vite multi-entry if CRXJS fails. |
| D-004 | Pin TypeScript 5.9, zod 3.25, Preact 10, Vitest 3, ESLint 9. | Newest majors (TS 7, zod 4, Preact 11, Vitest 5, ESLint 10) are too new for the ecosystem plugins (typescript-eslint, testing-library). |
| D-005 | Self-open suppression via a **self-view beacon** plus a ±20 s window, the 10 s post-send rule, and an `?s=` HMAC token for direct fetches. | GoogleImageProxy strips the sender's cookies/headers, so a header-based approach can't work for Gmail→Gmail. |
| D-006 | Dev-grade auth: `POST /v1/auth/register {email}` → random 32-byte token, stored as a sha256 hash. | Spec. Production plan: `chrome.identity.getAuthToken` → Google ID token verified server-side. |
| D-007 | Quiet hours are evaluated in the service worker. Suppressed notifications are summarised as one notification when quiet hours end. | The server doesn't know the user's timezone. |
| D-008 | `/v1/events` polling uses a server-issued opaque cursor (monotonic event id), not timestamps. `since=<iso>` is still accepted for compatibility. | Avoids clock skew between client and server. |
| D-009 | Gmail account switch reloads the page (`/u/N`), so each content-script instance reports exactly one account. The SW maps `tabId → account` in `chrome.storage.session`. | Matches Gmail behaviour; survives SW restarts. |
| D-010 | Docker base `node:20-bookworm-slim`. | `better-sqlite3` prebuilds need glibc. |
| D-011 | Server is bundled with esbuild (`server/build.mjs`); `better-sqlite3` stays external. `/shared` ships TS source (no build step). | One build artifact, no TS project-reference plumbing; Vite/vitest/tsx consume TS directly. |
| D-012 | Vitest 4.1.11 instead of 3.x. | 3.x pulls in tinypool with critical advisories (GHSA-5gmw-xhrv-c9v3); 4.1.11 is patched and supports Vite 6. |
| D-013 | `GET /v1/events` with neither `cursor` nor `since` returns no events plus the current high-water cursor. | A fresh install or re-login shouldn't replay historical notifications. |
| D-014 | Added `GET /v1/messages/:id/pixel` (owner only) and `PATCH /v1/reminders/:id`. | The simulate script needs the pixel URL. The service worker marks reminders fired/satisfied. |
| D-015 | Rate-limited pixel requests still get the GIF and rate-limited link clicks still redirect; neither is recorded. | Never break a recipient's email rendering or navigation. Redirects only go to registered URLs, so there's no abuse vector. |
| D-016 | `POST /v1/messages` with a `clientRequestId` that is already bound to a sent Gmail message → 409. | Prevents re-using one compose id for two different sends. |
| D-017 | CRXJS 2.7.1 works with InboxSDK; no fallback needed. Vite is pinned once at the root (6.4.3) to avoid duplicate type trees. | D-003 outcome. |
| D-018 | Tab scope = the tab's primary Gmail account plus the "Send as" aliases seen in that tab's compose windows (persisted per primary account). Gmail-facing surfaces filter by this set. | Otherwise mail sent via an alias would never show marks in the tab that sent it. |
| D-019 | Bus privilege is decided by sender URL: our `chrome-extension://<id>/` pages are privileged, everything else is treated as a content script limited to a whitelist. | The options page opens in a tab, so `sender.tab` can't tell the two apart (found by the Chrome load check). |
| D-020 | Sent-list marks use InboxSDK `ThreadRowView.addAttachmentIcon` with a Kefir-compatible live value (`LiveValue`: `onAny`/`offAny`), so marks update in place without re-rendering. | Spec 6.2 "refresh without full re-render". The attachment-icon column is right-aligned next to the date. |
| D-021 | `no_reply` reminders depend on replies the extension *observes* in Gmail (thread view / list rows) and reports via `REPORT_REPLY`. UI copy says "no reply detected". | The server can't see the mailbox; we never read mail content. |
| D-022 | Block InboxSDK telemetry with an isolated-world XHR/fetch guard (status 490), rather than a browser-wide declarativeNetRequest rule. | DNR would also block other InboxSDK-based extensions the user has installed. Our content-script world is private to us. |
| D-023 | Optional `RETENTION_DAYS` (default 0 = keep) plus automatic self-view cleanup every 6 h. | Data minimisation without surprising users by deleting history by default. |
| D-024 | Public rate limits: per-IP 1200/20 s⁻¹ plus per-(IP, resource) 20/0.2 s⁻¹. | Gmail's image proxy shares IPs across all Gmail recipients (C2). |
| D-025 | Server runs on **Cloudflare Workers + D1** (free, 24/7) as well as Node + better-sqlite3. Both use one Hono app over an async `SqlDb` interface (`server/src/db/sql.ts`); only positional `?` parameters (D1 has no named parameters). | The user wanted free, always-on hosting with no setup per session. Workers' free tier needs no card and no machine. |
| D-026 | No interactive transactions (D1 has none). Multi-step writes use atomic `batch()` (message + links; event insert + first-flag recompute; self-view + reclassify). Idempotent create handles a unique-constraint race by re-reading the existing row. Dedupe check → insert is not atomic; a rare duplicate under truly simultaneous hits is accepted (heuristic). | D1 constraints. |
| D-027 | On Workers: client IP from `CF-Connecting-IP` (set by Cloudflare, not spoofable); `PUBLIC_BASE_URL` defaults to the request origin (the permanent workers.dev URL); retention runs from a cron trigger every 6 h; per-install secrets are created lazily in D1's `meta` table. `node:net`/`Buffer` were replaced with portable code; `nodejs_compat` covers `node:crypto`. | Workers runtime. |
| D-028 | Deployments are locked to the owner via `ALLOWED_EMAILS` (set by the deploy script). Token recovery goes through `wrangler d1 execute`, so it needs the owner's Cloudflare login. Personal deploy config lives in git-ignored `server/wrangler.deploy.toml`. | A public workers.dev URL would otherwise let anyone register and use the free quota. |
| D-029 | Full per-email activity history (`GET_MESSAGE_EVENTS`): every event with plain-language source labels. "Ignored" events (MPP, scanners, own views) are hidden by default but one click away. Attribution is stated honestly: one recipient → "most likely theirs"; several → can't be attributed to a person (identical copies). | User asked for "who opened it and when". Per-recipient tracking for group emails was explicitly descoped. |
| D-030 | Wrangler 4.136.3 (dev-only). Its simulator pins vulnerable `undici`/`sharp`; overridden to patched 7.29.1 / 0.35.5 via root `overrides` (`npm audit`: 0). | Supply-chain hygiene. |
